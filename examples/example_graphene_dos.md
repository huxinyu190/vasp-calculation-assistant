# 使用案例 2：石墨烯态密度（DOS）计算——单项能力演示

这个案例演示**单项能力**的调用：用户只想要某个具体结果（DOS），以及如何用**输入文件校验**抓出并修复一个典型错误。

四个场景里第一个是**需求门禁**——它演示了另一件事：为什么同一个"算 DOS"的需求，石墨烯会被自动升到完整档，而案例 1 的硅只用精简档。

## 背景

石墨烯是二维蜂窝结构材料，是零带隙半导体（狄拉克点）。用户想算它的电子态密度（DOS），需要经历"结构优化 → SCF → DOS"三步。本案例聚焦 DOS 这一步，并展示校验能力的价值。

## 场景一：先过需求门禁（能力 0）——为什么它被升到完整档

用户说"帮我算石墨烯的 DOS"，Agent 先判档，不先写 INCAR：

| 判定项 | 石墨烯 | 结论 |
|---|---|---|
| 维度 | 单层蜂窝，z 方向要留真空 | **二维 → 触发「真空层」+「偶极修正」** |
| 磁性 / 电荷态 | 非磁 / 中性 | 不额外触发 |
| 目标 | 只有 DOS | 单目标，不触发组合任务 |

二维这一项一触发，精简档就不够用了——精简档根本没有「真空层」「偶极修正」这两栏。拿一份 `--level simple` 骨架填到只剩这两项空着，`--check` 会这样拦（实测输出）：

```
$ python scripts/intake.py --check intake_graphene_simple.md --content-only
[缺栏位] 真空层　（条件）
       为什么：表面与二维必须留足真空，厚度不够结果全是镜像相互作用
       怎么补：在确认单里加一行「- 真空层：」再填值
       或者：这一项属于完整档，直接重新生成更省事 ——
             python intake.py --new dos --level full

[缺栏位] 偶极修正　（条件）
       为什么：不对称 slab 不修偶极，功函数和吸附能都会偏
       怎么补：在确认单里加一行「- 偶极修正：」再填值
       或者：这一项属于完整档，直接重新生成更省事 ——
             python intake.py --new dos --level full

------------------------------------------------------------------
门禁结论：阻断（2 项缺栏位）
```

这就是「条件项一触发就升级」：不是流程喜欢多问，而是二维体系不问真空和偶极，算出来的 DOS 会被镜像层污染，而且 **VASP 不会报错**。

改成完整档重新生成骨架后，确认单里有几栏是精简档根本不会问的（完整单见 `examples/intake/intake_graphene_dos.md`）：

| 完整档独有栏位 | 本例填的值 | 为什么必须问 |
|---|---|---|
| 真空层 | 20 Å | 15 Å 起步、20 Å 更稳；厚度不够 = 层间耦合假象 |
| 偶极修正 | 关 | 单层上下对称、无净偶极；不对称体系不开会污染功函数 |
| 收敛测试 | ENCUT（400/480/520）+ k（18/24/30） | DOS 的精细结构对 k 密度极敏感 |
| 固定密度复用 | 是，dos 用 ICHARG=11 复用 static 的 CHGCAR | 三个阶段必须同盒子同网格，否则密度对不上 |
| 需要验证的项目 | k 密度、真空厚度、ENCUT 收敛 | 这些是"算完要回头查"的项，不写就会被忘掉 |

确认稿照例要交给用户过目，由用户自己回话才记录授权：

```
$ python scripts/intake.py --preview examples/intake/intake_graphene_dos.md
（渲染出分节确认稿，末尾给出内容指纹 aef895f89d7e）

$ python scripts/intake.py --approve examples/intake/intake_graphene_dos.md --by-user "可以，就这样"
已记录用户确认
指纹　：aef895f89d7e（绑定当前内容）
凭据　：examples/intake/intake_graphene_dos.approval.json
```

**门禁和校验是两道不同的关**：门禁拦的是"需求没定清楚就开工"，校验拦的是"文件写错了还去跑"。下面三个场景就是后一道关。

## 场景二：只调"输入文件校验"能力

用户手里已经有一份石墨烯的 DOS 输入文件，但他不确定对不对，于是说：

> 帮我检查一下这个石墨烯 DOS 计算的输入文件有没有错。

Agent 直接调用能力 2 的校验环节，运行 `validate_inputs.py`，并联网核对。

**发现的问题**（典型错误演示）：

```
[ERROR] 元素顺序不一致: POSCAR=['C'] vs POTCAR=['C','C']
         （POTCAR 被错误地 cat 了两遍，导致 4 原子石墨烯赝势重复）
[ERROR] ENCUT=300 低于 POTCAR ENMAX=400
[WARN] ISMEAR=1（金属用），但 DOS 计算建议用 ISMEAR=-5
```

Agent 的修复建议：
1. 重新生成 POTCAR：`cat /path/to/C/POTCAR > POTCAR`（只 cat 一次）
2. 提高 ENCUT 到 520（≥ 1.3 × ENMAX）
3. DOS 计算改 ISMEAR=-5，加 LORBIT=11、ICHARG=11

**修复后重新校验**（铁律：动过必重查）：
```
[PASS] 元素顺序一致
[PASS] ENCUT=520 ≥ 1.3×ENMAX
[PASS] ISMEAR=-5 适合 DOS
结论: 无 ERROR
```

## 场景三：只调"结果分析"能力

用户跑完 DOS 后，把结果发给 Agent 说：

> 帮我看看这个 DOS 结果对不对，符不符合石墨烯的物理特征。

Agent 调用能力 6，做物理合理性判断：

| 检查项 | 判断 |
|--------|------|
| 费米能级处 DOS | 石墨烯应为 0（狄拉克点零带隙），DOS 在 E_F 处接近 0 → 合理 |
| 价带/导带结构 | 上下近似对称 → 合理 |
| 有无明显带隙 | 若出现 > 0.5 eV 带隙 → 异常，可能是 k 点太疏或 ISMEAR 选错 |

Agent 输出结论：结果符合石墨烯的零带隙半导体特征，可信度中（建议加密 k 点提高 DOS 精度）。

## 场景四：单项调用"耗时估算"

用户问：

> 我这个 100 原子的石墨烯超胞算 DOS，128 核要多久？

Agent 调用能力 3：
```bash
python estimate_time.py --natoms 100 --nkpoints 1000 --encut 520 \
    --task dos --cores 128
```

输出：
```
估算单电子步耗时: 约 0.4 分钟
正式计算总耗时:   约 26.7 小时
置信度: 经验公式粗估（低置信度）
建议: 先做预计算实测校准，或评估是否可降低 k 点密度
```

## 案例要点总结

- **单项能力可独立调用**，Agent 会从提示词识别用户只要校验、只要分析、还是只要估时。
- **门禁先于一切**：同样是"算 DOS"，硅走精简档 14 栏，石墨烯因为"二维"触发真空层与偶极修正，被强制升到完整档。升档不是啰嗦，是这两栏不问就一定算错。这条规则由 `intake.py` 从已填内容自动推导，不靠 Agent 记性。
- **校验能力是保命能力**：本案例里元素重复、ENCUT 过低、ISMEAR 选错都是新手高频错误，不查直接跑会浪费大量机时甚至得出错误结论。
- **物理合理性判断**要结合材料特性（石墨烯零带隙），这正是"让不懂理论的小白也能判断对错"的关键。
