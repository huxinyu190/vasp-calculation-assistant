# 使用案例 3：多能力组合 + 智能路由演示

这个案例展示 **Agent 如何从提示词自动判断调用哪些能力**，以及一个更复杂的计算场景（多元素、多步流程）如何串联。

注意它的第一步不是资源调度、也不是写 INCAR，而是**需求门禁**：铁是磁性元素，磁态没定就不许生成。

## 场景：铁磁体 Fe 的磁矩计算

用户想算体心立方（BCC）铁（Fe）的磁矩。Fe 是铁磁金属，需要设置 MAGMOM，且是金属要用 ISMEAR=1。这是"金属 + 磁性"的进阶案例，涉及多个能力组合。

## 用户的第一句话

> 帮我算 BCC 铁的自发磁矩，我机器是 128 GB 内存、4 颗 16 核 CPU。另外我担心跑太久，先帮我估个时间。

Agent 的路由分析（能力 7）：

| 用户信号 | 识别到的能力 |
|---------|-------------|
| "帮我算 BCC 铁的磁矩"（终点是生成输入） | 0 需求门禁（先问清，再生成） |
| "机器是 128GB、4颗16核" | 能力 1 资源调度 |
| "算 BCC 铁的磁矩" | 能力 2 生成输入文件 |
| "担心跑太久，估个时间" | 能力 3 耗时估算 |

Agent 依次执行这些能力，并主动提示"建议先做预计算（能力 4）校准耗时"。

> **能力 0 为什么排在最前**：用户这句话的终点是"生成输入文件"，而"铁"是 3d 磁性元素——磁态没定就生成 INCAR，跑出来的可能是非磁解、也可能是低磁态，能量看着正常、结论全废。所以先过门禁。

## Agent 的输出

### 能力 0：需求门禁（磁性 → 完整档）

判档只需要两秒：含 3d 磁性元素 → 「磁性」这一项必须展开 → 初始磁矩、磁态约束都要问 → 精简档没有这些栏位 → **完整档**。

```bash
python scripts/intake.py --new energy --level full -o intake_fe_magnetism.md
```

填完的关键几栏（完整单见 `examples/intake/intake_fe_magnetism.md`）：

| 栏位 | 值 | 为什么不能省 |
|---|---|---|
| 关键物理 | 磁性=铁磁；电荷态=中性；+U=否；色散=关；SOC=关 | 五项逐项给值 |
| 初始磁矩 | Fe 2.3 μB/atom，两原子同向（MAGMOM = 2*2.3） | 起点若给成 1.0，可能收敛到低磁态 |
| 展宽 | ISMEAR=1、SIGMA=0.2 | 金属必须用 MP 展宽，SIGMA 过小 SCF 会震荡 |
| k 网格 | 12 12 12 | 磁矩随 k 点收敛慢，4×4×4 以下会给出偏小的磁矩 |
| 收敛测试 | k（8/12/16）+ ENCUT（400/520） | 判据是磁矩变化 < 0.02 μB，不是只看总能 |
| 需要验证的项目 | 磁态（2.3 与 3.0 两个起点是否同解）、k 收敛、SIGMA 影响 | 磁性体系最容易"换个起点换个答案" |

确认稿经用户过目、用户回话后才记录授权：

```
$ python scripts/intake.py --preview examples/intake/intake_fe_magnetism.md
$ python scripts/intake.py --approve examples/intake/intake_fe_magnetism.md --by-user "确认，按这个生成"
已记录用户确认
指纹　：39379eea2e3c（绑定当前内容）
凭据　：examples/intake/intake_fe_magnetism.approval.json
```

**这一步的产出不是文件，是一份"待验证清单"**：后面预计算（能力 4）要验磁态，结果分析（能力 6）要报磁矩与实验 2.22 μB 的偏差，两个环节的验收标准都来自这张单子。

### 能力 1：资源调度
```
总核心数 = 4 × 16 = 64
建议 NP=32, OMP=2
INCAR: KPAR=4（Fe 金属 k 点密，适合 k 点并行）
内存：Fe 原胞很小，64 核 128 GB 内存非常充足
```

### 能力 2：生成 + 校验输入文件

**POSCAR**（BCC Fe，2 原子原胞）：
```

```

**INCAR**（关键：金属 + 磁性）：
```

ENCUT = 520
PREC = Accurate
EDIFF = 1E-6
IBRION = -1
NSW = 0
ISMEAR = 1          ← 金属用 MP 展宽
SIGMA = 0.2

```

**校验**：
```
[PASS] 元素顺序一致
[PASS] ENCUT=520 ≥ 1.3×ENMAX
[PASS] ISPIN=2 自旋极化已开启（磁性计算必需）
[PASS] MAGMOM 已设置，原子数匹配
[WARN] ISMEAR=1 适合金属，正确
```

### 能力 3：耗时估算
```
体系：2 原子，8×8×8=64 k点，单点
经验粗估：几分钟级
置信度：低，建议预计算校准
```

## 用户接着追问（触发预计算）

> 先预计算一下，看看磁矩大概会是多少。

Agent 调用能力 4：
- 降级：ENCUT 降到 400，k 点降到 4×4×4，EDIFF 放宽到 1E-4
- 试算后反馈：
```
[预计算结论]
- 实际耗时：20 秒
- 磁矩趋势：约 2.2 μB/原子（接近实验值 2.22 μB！）
- 符合预期：是，BCC Fe 铁磁磁矩约 2.2 μB
- 校准耗时：正式单点预计 ~2 分钟
- 建议：正式计算保持 ENCUT=520、8×8×8，可精确得到磁矩
```

## 用户跑完正式计算（触发监控 + 报告）

> 跑完了，帮我分析结果出报告。

Agent 调用能力 5 + 6：
1. `monitor_to_csv.py` 整理日志为 `fe_monitor.csv`
2. `analyze_results.py` 提取磁矩
3. 生成报告：

```markdown
# VASP 计算报告：BCC Fe 自发磁矩

## 4. 结果数据
- 总磁矩：4.4 μB（2 原子，即 2.2 μB/原子）
- 实验值：2.22 μB/原子，误差 < 1%

## 5. 物理合理性分析
- 磁矩 2.2 μB 符合 Fe 铁磁实验值：合理
- 能量量级符合 BCC Fe：合理
- 金属性（ISMEAR=1）处理正确

## 6. 结论
- 满足需求：是
- 可信度：高（预计算趋势 + 正式结果 + 实验值三方吻合）
```

## 案例要点总结

1. **智能路由**：用户一句话里可以同时包含多个能力信号，Agent 逐一提炼。
2. **预计算的价值**：磁矩这种物理量，预计算就能看出"大约 2.2 μB"的趋势，让用户在正式算之前就有底。
3. **组合调用**：这个案例自然串联了 0→1→2→3→4→5→6 全部能力，展示了完整闭环。
4. **门禁在这里是"防错"而不是"走过场"**：磁性体系的初始磁矩和展宽决定收敛到哪个解，这两项一旦默认错，后面所有分析和实验对比都建立在一个错的磁态上。
5. **物理合理性对照**：磁矩、金属性、能量量级都有明确的实验/理论参照，小白也能判断"对不对"。
