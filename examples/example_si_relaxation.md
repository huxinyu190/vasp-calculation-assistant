# 使用案例 1：硅（Si）晶格常数优化——完整流程

这是最经典的入门案例：算单质硅的晶格常数。适合第一次用这个 Skill 的新手，走完能力 0~6 的完整闭环。

这个案例演示的是**精简档**：Si 是体相、非磁、中性、无缺陷、无吸附，所以需求采集只要 14 个必填栏位，不必把完整档的 43 栏问卷甩给你。

## 背景

硅是半导体，金刚石结构（FCC + 两原子基元）。实验晶格常数约 5.43 Å。我们要用 VASP 做结构优化，得到理论晶格常数，并和实验值对比。

## 第一步：告诉 Agent 你的需求（大白话）

你可以直接说：

> 我想算单质硅的晶格常数。我的机器是 64 GB 内存、2 颗 8 核的 CPU（总共 16 核）。帮我从头到尾跑一遍。

Agent 会自动路由：先过需求门禁（能力 0），再做资源调度（能力 1），然后生成输入文件（能力 2）、估算耗时（能力 3）、做预计算（能力 4），最后给你正式计算的建议和结果分析方法（能力 5、6）。

## 第二步：先过需求门禁（能力 0）

**在写任何一个输入文件之前，Agent 不会直接开工**，先把需求落成一份可以逐项核对的确认单。这一步是硬门禁：确认单没通过 `intake.py --check`（含用户二次确认），后面的能力全部不启动。

原因很直接——"算硅的晶格常数"这句话背后至少有四件事没定：算哪个量、什么模型、什么方法、什么精度。不确认就生成，错法是**静默**的：VASP 不报错，只是安静地算完一个物理上无意义的结果。

```bash
python scripts/intake.py --new relax --level simple -o intake_si_relax.md   # 1 生成骨架（阶段链已预填）
python scripts/intake.py --check intake_si_relax.md --content-only          # 2 边填边自检，不查授权
```

填好的确认单节选（完整单见 `examples/intake/intake_si_relax.md`）：

| 栏位 | 值 | 为什么这么填 |
|---|---|---|
| 科学问题 | PBE 弛豫的晶格常数与实验 5.43 Å 差多少，是否落在 PBE 已知偏差内 | 决定"算到什么程度算够" |
| 精度要求 | 定性趋势即可；晶格常数偏差 < 2% | 精度要求反过来定 ENCUT 与 k 点 |
| 关键物理 | 磁性=非磁；电荷态=中性；+U=否；色散=关；SOC=关 | 五项逐项给值，不许静默默认 |
| ENCUT | 520 eV | Si ENMAX=245.3，1.3×≈319，520 留余量 |
| k 网格 | 8 8 8 | 原胞近立方，三方向等密度 |
| 阶段链 | relax | 只要晶格常数，单阶段就够 |
| 核数 / 时限 | 8 核 / 2 小时 | 单作业约束，供能力 1 换算并行参数 |

内容齐全只说明"需求描述完整"，**不等于你同意按它生成**。所以还要把确认稿摆到你面前，由你自己说一句"确认"：

```
$ python scripts/intake.py --preview examples/intake/intake_si_relax.md
==================================================================
　VASP 输入需求确认单（生成前请核对）
==================================================================
任务：relax（几何优化（relax））
档位：simple　　阶段链：relax（单阶段，晶格与原子位置同时优化）

【物理模型】
  磁性：非磁　　电荷态：中性　　+U：否　　色散：关　　SOC：关

【方法与精度】
  泛函：PBE　　ENCUT：520 eV　　k 网格：8 8 8　　展宽：ISMEAR=0，SIGMA=0.05

【计算链】  阶段链：relax
【资源】    核数：8　　单作业时限：2 小时
------------------------------------------------------------------
确认单指纹：12d895f970b4
------------------------------------------------------------------
```

你回一句「确认生成，就按这个来」，Agent 才执行 `--approve`，把这句话连同一个内容指纹记成凭据：

```
$ python scripts/intake.py --approve examples/intake/intake_si_relax.md --by-user "确认生成，就按这个来"
已记录用户确认
时间　：2026-11-15 15:54
原话　：“确认生成，就按这个来”
指纹　：12d895f970b4（绑定当前内容）
凭据　：examples/intake/intake_si_relax.approval.json
```

**这层防护拦的是什么**：如果 Agent 在你确认之后又把 ENCUT 从 520 改成 480，`--check` 会立刻报 `[授权过期]`——你同意的是 520 那一版，改过就得重新给你看：

```
[授权过期] 用户二次确认　（授权）
       为什么：确认单在用户确认之后又被改过，之前那次同意已经不作数。
               重新 --preview 给用户看改动后的版本，再 --approve
```

想自己验证：把 `examples/intake/intake_si_relax.md` 和同目录的 `.approval.json` 复制一份，改掉 ENCUT 那一行的数值，再对副本跑 `--check`。

## 第三步：Agent 输出（资源调度，能力 1）

Agent 根据"64 GB 内存、16 核"给出：

```
[资源调度]
- 总核心数 = 2 × 8 = 16
- 建议 MPI 进程数 NP = 8，OpenMP 线程 OMP = 2
- INCAR 并行参数：NCORE = 4, KPAR = 1（Si 原胞 k 点不多）
- 可执行文件：vasp_std
- 内存：Si 原胞（2 原子）很小，单进程 < 1 GB，16 核 64 GB 内存绰绰有余
- 启动命令：mpirun -np 8 vasp_std
```


**POTCAR**：`cat /path/to/pot/Si/POTCAR > POTCAR`（元素顺序 Si，与 POSCAR 一致）

**KPOINTS**（半导体，中等网格）：
```
Automatic mesh
```


## 第五步：耗时估算（能力 3）

```
[耗时估算]
- 体系：8 原子，8×8×8=64 k点，ENCUT=520
- 经验粗估：单点约几分钟，结构优化约 1 小时内
- 置信度：低（未校准）
- 建议：先做预计算校准
```

## 第六步：预计算（能力 4）

Agent 建议把参数降级跑一次快试算：
- ENCUT 降到 400，k 点降到 4×4×4，EDIFF 放宽到 1E-4，NSW 只跑 5 步

试算结果反馈：
```
[预计算结论]
- 实际耗时：30 秒
- 能量趋势：从 -10.8 eV 降至 -10.9 eV，正常收敛
- 初始最大力：0.3 eV/Å，结构离平衡较近，正式优化预计 ~15 个离子步
- 单电子步实测耗时：0.5 秒 → 校准后正式计算预计 ~10 分钟
- 符合预期：是（能量量级符合 Si）
- 建议：ENCUT 保持 520，NSW 设为 50 足够
```

## 案例要点总结

这个案例演示了完整闭环：**需求门禁 → 资源调度 → 生成 → 校验 → 估算 → 预计算校准 → 监控 → 报告**。新手照做即可得到可信结果，关键是每一步 Agent 都给了"为什么"和"对不对"的判断。

前两步值得单独记一笔：**需求门禁管"要不要算这个"，资源调度管"怎么算得不崩"**。前者拦住的是白算几十小时，后者拦住的是跑崩机器。两个都是几分钟的事，跳过它们的代价要用机时来还。
