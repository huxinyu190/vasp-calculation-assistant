# 资源调度规则

根据虚拟机/服务器的硬件配置，给出 VASP 合理的并行计算资源分配建议。目标是**用有限的硬件，让计算跑得又快又稳，不内存溢出、不浪费核心**。

## 一、需要用户提供哪些信息

先向用户确认（缺哪个就问哪个）：
1. **总内存**（RAM，GB）
2. **CPU 型号**（影响每核性能，也决定是否支持 AVX 等指令集）
3. **CPU 数量**（物理 CPU 颗数）
4. **每颗 CPU 的核心数**
5. 是否跨节点（多机）运行（一般小白单机即可）

由此算出：**总核心数 = CPU 数量 × 每颗核心数**。

## 二、VASP 并行机制简述（大白话）

VASP 用 MPI（多进程）+ OpenMP（多线程）混合并行：
- **MPI 进程数（NP）**：把计算拆给多个进程，每个进程占独立内存。
- **OpenMP 线程数（OMP）**：每个进程内部再用多线程，共享该进程内存。
- 总核心数 = NP × OMP。

VASP 内部还有两个关键并行参数：
- **NCORE**：把每个能带的计算拆分到多个核心。设 NCORE=核心数，等于"关掉能带级并行，全用 k 点并行"。
- **KPAR**：k 点并行数。k 点多时增大 KPAR 很有效。
- **NPAR**：能带并行数，NPAR = 总核心数 / KPAR / NCORE 的搭配，通常设 NPAR 就够。

## 三、资源分配建议规则

### 1. 内存约束（最容易崩的地方）
- 估算单进程内存需求：与原子数、ENCUT、NBANDS 成正比。给出**可用的经验估算式**：
  - `单进程内存(GB) ≈ 原子数 × 0.02~0.05 GB`（ENCUT=520 左右、PBE 赝势、几十条能带的典型值）
  - 更精确做法：用 `vasp_std --dry-run` 看 OUTCAR 里报告的 `memory` 估算值，这是最可靠的。
- **铁律**：`NP × 单进程内存 < 总可用内存 × 0.8`（留 20% 余量给系统和缓存）。
- **判定动作**：
  - 估算总内存 < 可用内存 × 0.6 → 安全，直接跑
  - 0.6~0.8 之间 → 警告，建议减 NP 或增 NCORE 降内存峰值
  - > 0.8 → 必须警告，禁止硬跑，先减 NP 或增 NCORE
- 内存紧张时：减小 NP（进程越少，每进程分到内存越多），或增大 NCORE（降低每进程内存峰值）。

### 2. 进程/线程搭配
- **OMP 取值规则**：默认取 2；若单进程内存紧张，取 4（更大 OMP 会降低每进程内存峰值）。纯 MPI（OMP=1）仅在核心数 ≤ 8 时考虑。
- **NP 计算**：`NP = 总核心数 ÷ OMP`（向下取整，且要能被 KPAR 整除，见第 3 节）。
- 举例：16 核 → OMP=2，NP=8；32 核 → OMP=2，NP=16；64 核 → OMP=2，NP=32。
- 跨 NUMA 节点时，尽量让每个进程不跨 socket（用 `--map-by socket` 等 MPI 绑定参数），避免性能下降（高级话题，小白可略）。

### 3. NCORE / KPAR / NPAR
给出**具体取值规则**，不再含糊：

| 情形 | 判断标准 | 建议设置 |
|------|---------|---------|
| k 点多（金属、密集网格） | k 点数 ≥ 4× 核心数 | KPAR = 4 或 8（要求 NP 能被 KPAR 整除） |
| k 点少、能带多（大体系、单 k 点） | k 点数 < 核心数 | NCORE = OMP（等效关闭 k 点并行） |
| 一般情形（小白默认） | 拿不准 | KPAR = 1，NCORE = OMP，先跑试算 |

- **整除铁律**：NP 必须能被 KPAR 整除；NCORE 必须能被 (NP ÷ KPAR) 整除。
- **简化流程（小白友好）**：
  1. 先设 `KPAR = 1`、`NCORE = OMP` 跑一次预计算
  2. 若预计算显示 k 点很多（> 4× 核心数），把 KPAR 调成 4，再实测对比耗时
  3. 选实测最快的组合

### 4. 选哪个可执行文件
| 场景 | 可执行文件 |
|------|-----------|
| 普通计算 | vasp_std |
| 只用 Γ 点（分子、大超胞） | vasp_gam（更快） |
| 非共线磁性 / 自旋轨道 | vasp_ncl |

### 5. 输出建议格式
给用户一份可复制的并行设置：
```
建议配置：
- MPI 进程数 NP = 16
- OpenMP 线程数 OMP = 2
- 总核心使用 = 32
- INCAR 增加：NCORE = 4, KPAR = 4
- 启动命令：mpirun -np 16 vasp_std
- 预计单进程内存 ~X GB，总内存占用 ~Y GB，安全
```

## 四、边界与降级

- 如果用户给不全硬件信息，先用**能拿到的参数**给出保守建议（进程数 = 核心数、OMP=1），并说明"补齐信息后可进一步优化"。
- 如果内存明显不够，**必须明确警告**，不要硬跑。
- 所有建议都是**基于经验的推断**，最优配置最终要靠预计算（能力 4）实测确认。
