# 耗时估算规则

估算一次 VASP 计算的完成时间。分两步：**先用经验公式粗估量级**，**再用预计算实测校准**。最终给出「预计算时长」和「正式计算时长」两个估计值。

## 一、影响耗时的因素

| 因素 | 影响 |
|------|------|
| 原子数 N | 越大越慢（大致 N²~N³ 量级） |
| k 点数 | 越多越慢（近似线性） |
| ENCUT | 越高越慢（平面波数 ≈ ENCUT^1.5） |
| 电子步数 | SCF 循环次数，与收敛难度相关 |
| 离子步数 NSW | 结构优化时每个离子步都包含若干电子步 |
| 计算类型 | 单点 < 结构优化 < DOS/能带 < 杂化泛函/GW（贵一个数量级甚至更多） |
| 硬件 | 核心数、CPU 型号、内存带宽 |

## 二、经验公式粗估（第一步）

单电子步（单 k 点单能带贡献）的耗时，粗略可写成：

```
单电子步耗时 t_scf ≈ C × (N^α) × (N_k) × (Ecut/400)^1.5 / (NP × 单核频率因子)
```

- N：原子数
- N_k：k 点数
- α：经验指数，约 2~3（脚本默认取 **2.5**，小体系可调小到 2、大体系可调大到 3）
- C：经验常数，脚本 `estimate_time.py` 中取 **3e-5**（单位秒，按中等 CPU、PBE 赝势、Normal 算法校准）
- 单核频率因子：脚本中按 1.0（以 3 GHz 为基准）

> 注：脚本里 C=3e-5、频率因子=1.0 是固定默认值。若已知用户 CPU 型号与 3 GHz 基准差异较大，可在脚本中相应调整，但文档与脚本默认值必须保持一致。

**实用做法**：因为 C 和 α 很难事先精确知道，粗估主要用于给出**量级**（分钟 / 小时 / 天），并据此判断参数是否合理（比如"你这个 k 点太密，要跑一个月，建议先降"）。

典型量级参考（中等 CPU，几十核，粗估）：

| 体系规模 | 单点能 | 结构优化 |
|---------|--------|---------|
| < 20 原子 | 分钟级 | 分钟~小时 |
| 20~100 原子 | 分钟~小时 | 小时级 |
| 100~500 原子 | 小时级 | 小时~天 |
| > 500 原子 | 天级 | 天~周 |

## 三、预计算校准（第二步，关键）

正式估算前，用能力 4 的预计算实测得到**单电子步真实耗时**，再外推：

```
正式总耗时 ≈ 实测单电子步耗时 × 预计电子步总数
```

- **预计电子步总数** = 平均每离子步电子步数 × 离子步数（结构优化）；单点则直接 = SCF 收敛所需电子步数。
- **电子步数经验默认值**（脚本 `estimate_time.py` 默认 `--scf-per-step 40`）：
  - 单点/普通 SCF：约 20~40 步
  - 结构优化：平均每离子步 30~50 步（取 40 为默认）
  - 难收敛体系（金属、磁性、表面）：可上调到 60~80 步
- 预计算用**降低后的参数**跑（ENCUT 降低、k 点减少、EDIFF 放宽），因此实测耗时需要**按参数放大**回正式计算的规模：

```
正式单电子步耗时 ≈ 实测单电子步耗时 × (Ecut正式/Ecut预)^1.5 × (Nk正式/Nk预) × (N正式/N预)^α
```

## 四、输出格式

给用户一份清晰的时间表：

```
[耗时估算]
- 预计算：约 X 分钟（用降级参数）
- 正式计算：
  - 单点能：约 Y 分钟
  - 结构优化（预计 Z 个离子步）：约 W 小时
- 置信度：基于预计算实测校准（高）/ 仅经验粗估（低）
- 建议：若超出可接受时间，可降低 k 点 / ENCUT / 收敛标准
```

## 五、边界与诚实声明

- 所有估算**只是估计**，实际受收敛难度、负载、I/O 影响。
- 预计算校准前的数字标注为「量级粗估」，校准后的标注为「实测校准估计」。
- 明确区分「已实测」「推断」「未验证」，不把推断写成事实。
