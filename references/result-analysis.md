# 结果分析与报告规则

计算跑完后，判断结果是否**满足用户需求**、是否**符合真实物理规律**，并输出一份完整的 Markdown 计算报告。

## 一、结果分析要回答三个问题

1. **算完了吗？**（技术层面：是否正常收敛）
2. **算对了吗？**（物理层面：结果是否合理可信）
3. **算的是用户想要的吗？**（需求层面：是否达到最初目标）

## 二、技术层面：收敛性判断

从输出文件（OUTCAR/OSZICAR）检查：

- [ ] **电子收敛**：OUTCAR 出现 `reached required accuracy` 或能量差 < EDIFF
- [ ] **离子收敛**（结构优化）：OUTCAR 出现 `reached required accuracy - stopping structural energy minimisation`，或最大力 < EDIFFG
- [ ] **是否达到 NSW/NELM 上限**：如果步数用满还没收敛，说明**没算完**，需增加步数或调参数继续
- [ ] **能量单调性**：能量是否稳定下降/收敛，有无发散或剧烈抖动

## 三、物理层面：合理性判断

这是"结果对不对"的关键，要结合物理常识：

| 检查项 | 合理范围 / 判据 | 异常提示 |
|--------|----------------|---------|
| 能量量级 | 每原子能量约 -1 ~ -10 eV 量级（视元素） | 离谱说明结构/赝势错 |
| 键长 | 与已知实验/文献值接近（误差 < 5%） | 明显偏差要核查 |
| 原子间距 | 无异常接近（< 0.8 Å 通常有问题） | 结构重叠 |
| 带隙符号 | 半导体带隙 > 0；金属无带隙 | 符号反了 = 泛函/展宽错 |
| 磁性 | 磁矩符合元素预期（如 Fe、Ni 有磁矩） | 异常要查 MAGMOM |
| 晶格常数 | 与实验值误差 < 2~3%（DFT 系统误差内） | 过大偏差核查 ENCUT/k 点 |
| 力 | 优化后最大力应接近 0 | 未收敛 |

**联网核对**：关键物理量（晶格常数、键长、带隙）可对照 Materials Project（https://materialsproject.org/）、ICSD（https://icsd.products.fiz-karlsruhe.de/）、文献值核验，具体网址清单见 `online-resources.md`。带隙偏小是 PBE 泛函的已知系统性问题（低估 ~30%），属于正常现象，报告里要说明。

## 四、需求层面：是否满足用户目标

对照用户最初的需求逐项确认：
- 用户想算晶格常数 → 给出优化后的晶格常数 + 与实验对比
- 用户想算带隙 → 给出带隙值 + 说明泛函低估的修正
- 用户想算吸附能 → 给出能量差 + 判断吸附是否稳定
- 用户想算 DOS/能带 → 确认图线形态合理

**没满足的需求要明确列出**，并说明原因和下一步。

## 五、报告模板（Markdown）

报告统一用下面结构，输出到当前目录：

```markdown
# VASP 计算报告：<体系名称 / 计算类型>

## 1. 计算概述
- 计算目的
- 体系描述（元素、原子数、晶胞）
- 计算类型（单点/优化/DOS/能带等）

## 2. 计算设置
- 硬件与并行配置
- 四大输入文件关键参数（表格）
- 预计算情况（如有）

## 3. 收敛情况
- 电子收敛：是否达标、最终能量差
- 离子收敛：是否达标、最终最大力
- 使用步数 / 最大步数

## 4. 结果数据
- 总能量、每原子能量
- 结构参数（晶格常数、键长，如有优化）
- 目标物理量（带隙、磁矩、吸附能等）

## 5. 物理合理性分析
- 逐项对照判据，标注 合理/异常
- 与文献/数据库对比
- 已知的系统性误差说明（如 PBE 带隙低估）

## 6. 结论
- 是否满足用户需求（明确 是/否/部分）
- 结果可信度评价
- 遗留问题与建议的下一步

## 7. 附录
- 输入文件摘要
- CSV 监控数据位置（如有）
- 参考来源
```

## 六、诚实原则

- **结果可信度分档**（给出明确判据，不凭感觉）：
  - **高**：满足以下全部——① 电子与离子都收敛；② ENCUT 和 k 点做了收敛性测试且达标；③ 物理量合理且与文献/数据库误差在系统误差范围内（晶格常数 < 2%、键长 < 5%）
  - **中**：满足 ①，但 ② 或 ③ 有一项未做/存疑
  - **低**：① 未收敛，或 ②③ 都缺失，或结果出现明显异常
- 发现的异常**必须如实写**，不能为了"好看"隐瞒。
- 区分「已实测」「推断」「未验证」。
- 报告中不夸大、不虚构数据，所有数字都来自实际输出文件。
