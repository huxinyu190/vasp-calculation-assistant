# 环境与性能测试（能力 8）

> 目标：在正式计算前，用最短时间确认「VASP 能否正常跑」和「这台虚拟机实际性能如何」。测试结果用于校准耗时估算（能力 3），让预估从"拍脑袋"变成"实测外推"。

---

## 一、这个测试要回答两个问题

| 问题 | 目的 | 失败意味着什么 |
|------|------|--------------|
| **1. VASP 能正常用吗？** | 验证可执行文件、库、MPI、赝势路径都正常 | 编译/环境/许可问题，必须修好才能算 |
| **2. 这台机器有多快？** | 实测单电子步耗时，得到**性能基准** | 直接决定耗时估算的准确度 |

## 二、测试方法（三步走）

### 步骤 1：确认 VASP 可执行文件与版本

先找到 VASP 二进制文件在哪，并确认版本：

```bash
which vasp_std          # 找标准版
vasp_std --version 2>&1 | head -5   # 看版本号（若支持）
```

**判读**：
- 找不到 `vasp_std` → 环境变量 PATH 没配好，先解决路径
- 找到但 `--version` 报错 → 可能缺动态库（`ldd vasp_std` 看缺什么）
- 有 `vasp_std`（标准）、`vasp_gam`（Γ点专用）、`vasp_ncl`（非共线磁性）三个版本，按需选用

### 步骤 2：跑最小测试体系（冒烟测试 smoke test）

用一个**极小的体系**（如 2 个 Si 原子或 1 个 O₂ 分子），跑一次单点能（不优化），确认整个链路能走通。这一步**应该几秒内完成**。

测试脚本会自动生成最小输入文件并给出运行命令，见 `scripts/test_environment.py`。

**判读标准**：
- 出现 `reached required accuracy` 或正常的 `General timing` 块 → ✅ VASP 可用
- 报错 → 按错误类型排查（见第四节）

### 步骤 3：性能基准测试（benchmark）

用一个**中等规模、固定参数**的体系（如 8~32 原子的 Si 超胞，固定 ENCUT、k 点），跑若干电子步，**实测单电子步耗时**。这个数值就是你的"机器性能基准"。

**关键**：基准测试的参数必须**固定且可复现**，这样不同机器、不同配置之间才能公平对比。

## 三、性能基准的判读与反哺

### 3.1 得到"单电子步耗时"基准

性能测试的核心输出是一个数：**这台机器在这套参数下，单电子步平均耗时 T_step（秒）**。

### 3.2 反哺耗时估算（能力 3）

把这个实测值喂给耗时估算脚本，就能把"经验公式粗估（低置信度）"升级为"实测校准（高置信度）"：

```bash
python scripts/estimate_time.py \
  --natoms 32 --nkpoints 64 --encut 520 --task relax --nionic 50 --cores 64 \
  --measured-scf-time <实测单步耗时> \
  --measured-encut 400 --measured-nk 8 --measured-natoms 8
```

### 3.3 性能基准参考量级（经验值）

不同硬件下，单电子步耗时量级差异巨大，给出粗略参考（8 原子 Si、ENCUT=400、Γ点，单核）：

| 硬件档次 | 单电子步耗时量级 | 说明 |
|---------|----------------|------|
| 老旧台式机/笔记本 | 10~60 秒 | 只能算几十原子小体系 |
| 普通工作站（16~32 核） | 1~10 秒 | 可算百原子级 |
| 高性能集群（百核+） | 0.1~1 秒 | 可算数百原子 |

> 注意：这只是极粗略参考。真实性能受 CPU 型号、频率、内存带宽、是否跨 NUMA、编译优化（MKL/OpenBLAS/FFT 库）影响巨大，**务必以实测为准**。

## 四、常见失败与排查

| 现象 | 可能原因 | 排查动作 |
|------|---------|---------|
| `command not found: vasp_std` | PATH 没配 | `echo $PATH` 找 vasp 目录，或用绝对路径 |
| `error while loading shared libraries` | 缺动态库 | `ldd vasp_std` 看缺哪些 .so |
| `MPI error` / 进程数超限 | 请求核数 > 可用核 | 减小 `-np` 到实际物理核数 |
| `insufficient memory` | 内存不足 | 减小 NP、增大 NCORE，或用能力 1 重新调度 |
| 跑得极慢（远低于预期） | 跨 NUMA、超线程、负载过高 | 检查 CPU 亲和性，关超线程，看 `top` 负载 |
| 输出只有几十行就停了 | 输入文件错（POSCAR/POTCAR 不匹配） | 回到能力 2 校验输入文件 |

## 五、测试脚本用法

```bash
# 冒烟测试：自动生成最小体系并给出运行命令
python scripts/test_environment.py --vasp vasp_std --cores 4

# 性能基准：指定体系规模
python scripts/test_environment.py --vasp vasp_std --cores 64 \
  --natoms 8 --encut 400 --kmesh "1 1 1" --nsteps 20
```

脚本会：
1. 生成最小测试输入文件（放在当前目录 `test_env/` 子目录）
2. 打印 VASP 运行命令（Agent 不直接执行，用户/调度系统去跑）
3. 提供解析结果、提取单步耗时的辅助函数
4. 输出性能基准建议（喂给能力 3）

## 六、核心铁律

1. **正式计算前必做冒烟测试**：连最小体系都跑不通，正式计算必然失败。
2. **性能基准参数必须固定可复现**，否则无法跨机器对比、无法反哺估算。
3. **测试结果如实记录**（版本、核心数、单步耗时、日期），作为耗时估算的依据。
4. 测试产生的临时文件放**当前工作目录**（`test_env/`），不写系统临时目录。
5. 测试不通过（VASP 报错）时，**先修环境再谈计算**，不要跳过。
